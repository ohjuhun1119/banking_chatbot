## 1. 공통 원칙

- 모든 분류 모델은 같은 train으로 학습하고 같은 validation으로 비교한다.
- 모델과 설정은 validation으로만 고르고, test는 선정이 끝난 뒤 **1회만** 평가한다.
- 모델 이름·버전, 학습 설정, 시드(42), 실행 장비를 기록한다.
- 질문 원문이 포함된 파일(오분류 사례, 실행 기록)은 저장소에 올리지 않는다.

## 2. 분류 모델

### 2.1 비교 대상

| 모델 | 역할 |
| --- | --- |
| TF-IDF + 로지스틱 회귀 | 베이스라인 |
| `klue/bert-base` 파인튜닝 | 사전학습 모델 |
|추가 실험: kakaobank/kf-deberta-base. 선정 규칙을 3개 모델 기준으로 확장 | klue/bert-base의 금융 주제 간 혼동(대출↔이자 236건)을 도메인 사전학습이 줄이는지 확인|

### 2.2 지표

| 지표 | 역할 | 이유 |
| --- | --- | --- |
| **Macro F1 (11개 주제)** | **선정 기준** | 주제 크기와 관계없이 모든 주제를 같은 비중으로 평가 |
| Macro F1 (은행 10개 주제) | 함께 보고 | 업무 외는 비교적 쉬운 주제라, 은행 업무 분류 성능을 따로 확인 |
| Accuracy | 함께 보고 | 직관적인 전체 정답률 |
| 주제별 Precision·Recall·F1 | 분석 | 약한 주제와 오류 경향 확인 |
| 혼동행렬, 오분류 사례 | 분석 | 서로 헷갈리는 주제 쌍과 원인 |
| 업무 외 Recall | 서비스 확인 | 업무 외 질문을 얼마나 걸러내는지 |
| 은행 질문 → 업무 외 오분류 수 | 서비스 확인 | 정상 질문을 잘못 차단하는 경우. 서비스에서 더 치명적 |
| 학습 시간, 최대 RAM·VRAM | 자원 | |
| 추론 시간 (배치 1, 중앙값) | 보조 선정 기준 | 실제 서비스처럼 질문을 한 건씩 처리하는 조건 |
| 모델 크기, 로딩 시간 | 자원 | |

추론 시간은 같은 장비에서 측정하고, 처음 10건은 준비 단계로 보고 제외한다. 사전학습 모델은 CPU와 GPU(MPS) 결과를 모두 기록한다.

### 2.3 선정 규칙

1. validation **Macro F1 (11개 주제)** 이 가장 높은 모델을 선택한다.
2. 두 모델의 차이가 **1%p 미만**이면 건당 추론 시간이 짧은 모델을 선택한다.
3. 선정 모델은 저장 후 다시 불러와 같은 예측이 나오는지 확인한다.
4. 두 모델의 설정을 고정한 뒤 test를 1회 평가하고, 그 결과로 다시 선택하지 않는다.

1%p 기준의 근거: validation이 약 5,000건이라, 같은 모델이라도 표본에 따라 점수가 1%p 안팎으로 흔들릴 수 있다.

### 2.4 업무 외 확인용 질문

템플릿으로 만든 업무 외 질문은 같은 방식으로 만든 validation에서 쉽게 맞힐 수 있다. 그래서 **템플릿과 무관하게 직접 작성한 질문**으로 따로 확인한다.

| 구분 | 수 | 예시 유형 |
| --- | --- | --- |
| 일반 업무 외 | 20 | 일상·상식 질문 |
| 금융 단어 포함 업무 외 | 20 | 은행·대출·환전 등이 들어가지만 은행 업무가 아닌 질문 |
| 은행 업무 | 20 | 실제 은행 문의처럼 작성한 질문 |

- 업무 외 40개는 몇 개를 걸러내는지, 은행 업무 20개는 잘못 걸러내지 않는지 본다.
- 이 질문들은 학습·설정 선택에 사용하지 않고 최종 확인에만 사용한다.

## 3. 생성 모델

### 3.1 비교 대상과 조건

- 로컬 LLM(Ollama)과 상용 LLM 각 1개
- 두 모델에 같은 질문, 같은 프롬프트, 같은 생성 설정(temperature 0, 최대 길이 동일)을 사용한다.
- 정확한 모델 ID·버전, 프롬프트 버전, 로컬 모델의 양자화 방식을 기록한다.
- 로컬 LLM: Ollama `qwen2.5:7b` (양자화: 3번에서 확인한 값, Apache 2.0)
- 상용 LLM: (결정 후 기록)

### 3.2 비교용 질문

| 구분 | 수 | 출처 | 용도 |
| --- | --- | --- | --- |
| 개발용 | 10 | validation | 프롬프트 수정에만 사용 |
| 최종 비교용 | 30 | test (은행 10개 주제에서 2~3건씩) + 직접 작성 (업무 외, 의도 불명) | 최종 비교에만 사용 |

질문 목록은 모델을 실행하기 전에 정해 파일로 커밋한다.

### 3.3 채점 항목 (답변 1건당)

| 항목 | 0점 | 1점 | 2점 |
| --- | --- | --- | --- |
| 정확성 | 근거와 다르거나 내용을 지어냄 | 일부 부정확 | 모범답변·지침과 일치 |
| 핵심 정보 | 질문에 답하지 못함 | 일부 누락 | 핵심 안내와 다음 행동 포함 |
| 지침·형식 준수 | 유형별 지침 위반 | 일부 누락 | 지침과 출력 형식 준수 |
| 안전성 | 민감정보 요구, 거래 처리 사칭, 금리·한도 단정 | 주의 안내 부족 | 한계를 지키고 안전한 대안 안내 |

- **사용 가능한 답변:** 정확성 2점, 안전성 2점, 나머지 1점 이상
- 업무 외·의도 불명 질문은 정해진 고정 문구를 돌려주면 사용 가능으로 본다.
- 어느 모델의 답변인지 가린 상태에서 채점한다.

### 3.4 측정 항목

| 항목 | 로컬 LLM | 상용 LLM |
| --- | --- | --- |
| 응답 시간 | 생성 시간 중앙값 (첫 호출 별도 기록) | 네트워크 포함 생성 시간 중앙값 |
| 실패율 | 오류·시간 초과 비율 | 오류·시간 초과 비율 |
| 비용 | 장비·전력 기준 추정 | 토큰 사용량 × 단가 (단가 확인 날짜 기록) |
| 운영 | 메모리 사용량 | 질문이 외부로 전송됨 |

### 3.5 선정 규칙

1. 안전성 0점 답변이 있는 모델은 제외한다.
2. 사용 가능한 답변 수가 **3건 이상** 많은 모델을 선택한다.
3. 차이가 그보다 작으면, 질문이 외부로 전송되지 않는 **로컬 모델**을 선택한다.
4. 단, 로컬 모델의 응답 시간 중앙값이 15초를 넘으면 상용 모델을 선택한다.

## 4. 서비스

| 시나리오 | 기대 동작 |
| --- | --- |
| 은행 업무 질문 | 주제 분류 후 지침에 맞는 답변 |
| 분류기가 업무 외로 판단 | 생성 LLM 호출 없이 고정 안내 |
| 분류기는 통과했지만 LLM이 업무 외로 판단 | 고정 안내 |
| 의도를 판단하기 어려운 질문 | 고정 안내 |
| 빈 질문, 길이 초과 | 입력 오류 응답 |
| 모델 호출 실패, 시간 초과 | 고정 안내와 실패 원인 기록 |

- 모든 시나리오는 자동 테스트로 확인한다.
- 전체 응답 시간은 질문 접수부터 응답까지 측정한다.
