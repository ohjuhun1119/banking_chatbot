# 추가 실험: 금융 도메인 사전학습 모델

## 동기
klue/bert-base는 베이스라인보다 Macro F1이 2.34%p 높았지만,
대출문의 ↔ 이자/연체금액 혼동이 236건으로 전체 오분류(약 925건)의 약 25%를 차지했다.
거래내역 → 이자/연체금액(60건)까지 포함하면 금융 개념이 겹치는 주제 사이 혼동이 가장 큰 약점이다.

## 가설
범용·금융 말뭉치로 사전학습한 kakaobank/kf-deberta-base는
금융 용어와 개념의 관계를 더 잘 이해해, 이 혼동을 줄이고 은행 10종 Macro F1을 높일 것이다.

## 방법
- 모델: kakaobank/kf-deberta-base (MIT 라이선스)
- klue/bert-base와 같은 분할, 같은 학습 설정 (max_length 128, batch 32, lr 2e-5, 3 epoch)
- 같은 평가 지표, 특히 대출문의 ↔ 이자/연체금액 오분류 수를 비교
- 학습 장치: MacBook CPU
  - MPS(Apple GPU)로 학습 시 DeBERTa의 일부 연산이 MPS를 지원하지 않아 CPU로 전환되며 스텝당 19.5초가 걸렸다.
  - CPU 전용으로 학습하니 스텝당 2.5초로 약 8배 빨라져 CPU로 학습했다.
  - klue/bert-base는 MPS로 학습했으므로 **학습 시간은 직접 비교하지 않는다.**
  - 성능(Macro F1)은 같은 데이터·같은 학습 설정이므로 비교 가능하다.
  - 추론 시간은 세 모델 모두 같은 맥의 CPU 기준(배치 1 중앙값)으로 비교한다.

## 결과
| 지표 | klue/bert-base | kf-deberta-base |
| --- | --- | --- |
| Macro F1 (11종) | 0.7274 | 0.7243 |
| Macro F1 (은행 10종) | 0.7002 | 0.6968 |
| 대출문의 ↔ 이자/연체금액 혼동 | 236건 | 232건 |
| 추론 시간 (CPU 중앙값) | 0.014초 | 0.028초 |
| 모델 크기 | 423MB | 712MB |

- 학습 장치: klue/bert-base는 MPS, kf-deberta-base는 CPU (MPS에서 DeBERTa 일부 연산 미지원으로 스텝당 19.5초 → CPU 2.5초). 학습 시간·메모리는 비교하지 않음.

## 결론
- **가설은 지지되지 않았다.** 금융 도메인 사전학습 모델도 대출 ↔ 이자 혼동을 줄이지 못했다(236 → 232건).
- 이 혼동은 금융 용어 이해의 문제라기보다, 대출 상담 중 이자·상환을 묻는 질문처럼 **두 주제에 모두 해당하는 라벨 경계의 모호성**에서 비롯된 것으로 판단한다.
- 성능 차이(−0.31%p)는 선정 기준(1%p) 안이고, 추론 시간은 약 2배, 모델 크기는 약 1.7배라 **서비스 모델은 klue/bert-base를 유지**한다.
- 한계: 시드 1회 학습이라 0.3%p 수준의 차이는 우연일 수 있다.

### 직접 작성한 확인용 질문 (60개)

| 모델 | 업무 외 검출 (40) | 은행 업무 통과 (20) |
| --- | --- | --- |
| TF-IDF + LR | 22 | 19 |
| klue/bert-base | 38 | 18 |
| kf-deberta-base | 39 | 19 |


- validation에서는 세 모델 모두 업무 외를 거의 완벽하게 맞혔지만, 템플릿과 무관한 질문에서는
  베이스라인이 40개 중 22개만 걸러내 **단어 기반 분류의 한계**가 드러났다.
- 두 사전학습 모델은 비슷한 수준이었고, kf-deberta가 2개 더 맞혔으나 60개 기준이라 차이를 단정하기 어렵다.
- "통장 비번 까먹었어요"처럼 **기타(은행)에 해당하는 질문이 업무 외로 차단**되는 문제가 발견되었다.
  두 BERT 모델 모두 기타(은행)을 예측하지 못해, 해당 질문이 업무 외로 분류된 것으로 보인다.
- 사전에 정한 규칙(확인용 질문은 선정에 사용하지 않음)에 따라 선정은 klue/bert-base를 유지하고,
  업무 외 오차단은 서비스 설계(확신도 기준 + LLM 2차 확인)로 보완한다.
